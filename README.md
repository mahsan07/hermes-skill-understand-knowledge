# Understand Knowledge

> Analyze a Karpathy-pattern LLM wiki and generate a knowledge graph with entities and topic clusters.

This repository packages one focused Hermes skill as a public, documentation-first capability. The blueprint below explains the actual operating surfaces, control points, failure paths, and evidence expected from a trustworthy run.

![Detailed systems blueprint for Understand Knowledge](assets/system-blueprint.png)

## The problem it solves

Research is hard to trust when source collection, interpretation, and conclusions are not visibly connected.

## System components

- **Markdown knowledge base**
- **Entity extractor**
- **Explicit and implicit links**
- **Topic clustering**
- **Knowledge dashboard**

## Execution walkthrough

1. **Index notes headings links and citations**
2. **Extract people concepts artifacts and claims**
3. **Connect explicit backlinks and inferred relations**
4. **Score and label implicit relationships**
5. **Cluster topics and bridge nodes**
6. **Render a queryable knowledge graph**

## Example request

> For a narrow, non-sensitive research question, analyze a Karpathy-pattern LLM wiki and generate a knowledge graph with entities and topic clusters. Return the result, the evidence used to verify it, and any limitations or actions that still require approval.

## Evidence contract

- `request.json` — captures request.
- `inspection.json` — captures inspection.
- `preview.json` — captures preview.
- `execution.json` — captures execution.
- `verification.json` — captures verification.
- `receipt.json` — captures receipt.

A run is complete only when the final artifact can be reopened or re-read and compared with the requested acceptance criteria. An attempted command or successful API response alone is not sufficient proof.
